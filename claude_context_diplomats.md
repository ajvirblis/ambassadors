# Project Context: Russian MFA Diplomats Pipeline

## Overview

- **Database:** `declarator_prod` (PostgreSQL)
- **Working schema:** `jvirblis`
- **Access:** via SSH tunnel (`sshtunnel` + `psycopg2`)
- **Client:** DBeaver
- **Project:** declarator.org — archive of financial declarations of Russian public officials

---

## Database Connection (standard pattern)

```python
from sshtunnel import SSHTunnelForwarder
import psycopg2
from config import (
    SSH_HOST, SSH_PORT, SSH_USER, SSH_KEY_PATH, SSH_KEY_PASSWORD,
    DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD
)

with SSHTunnelForwarder(
    (SSH_HOST, SSH_PORT),
    ssh_username=SSH_USER,
    ssh_pkey=SSH_KEY_PATH,
    ssh_private_key_password=SSH_KEY_PASSWORD,
    remote_bind_address=(DB_HOST, DB_PORT)
) as tunnel:
    conn = psycopg2.connect(
        host='127.0.0.1',
        port=tunnel.local_bind_port,
        dbname=DB_NAME,
        user=DB_USER,
        password=DB_PASSWORD
    )
```

Never connect directly to `DB_HOST:5432` — the port is blocked externally.

## Source Table: jvirblis.diplomats

```sql
CREATE TABLE jvirblis.diplomats (
    id              INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    actuality_date  DATE NOT NULL DEFAULT '2026-04-06',
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    body            JSONB,
    person_id       INTEGER REFERENCES public.declarations_person(id) ON DELETE SET NULL
);
```

- **666 records**, data current as of 2026-04-06
- Source: Russian MFA website

### body fields

| Field | Description | Example |
|---|---|---|
| `family_name` | Surname (CAPS) | `"АГАСАНДЯН"` |
| `name` | First name (CAPS) | `"МИКАЭЛ"` |
| `patronymic` | Patronymic (CAPS) | `"ВАДИМОВИЧ"` |
| `dob` | Date of birth | `"18.04.1973"` |
| `department` | Department or embassy | `"ПЕРВЫЙ ДЕПАРТАМЕНТ СТРАН СНГ"` |
| `position` | Job title | `"ДИРЕКТОР ДЕПАРТАМЕНТА"` |
| `diplomatic_rank` | Diplomatic rank | `"ЧРЕЗВЫЧАЙНЫЙ И ПОЛНОМОЧНЫЙ ПОСОЛ"` |
| `rank_acquisition_date` | Date rank was assigned | `"11.06.2025"` |
| `url` | Source page URL (must be saved by scraper) | `"https://mid.ru/..."` |

### Extracting fields from body

```sql
body->>'family_name'
body->>'name'
body->>'patronymic'
body->>'dob'                   -- text DD.MM.YYYY
body->>'rank_acquisition_date' -- text DD.MM.YYYY
body->>'url'                   -- source URL

-- Parse dates:
to_date(body->>'dob', 'DD.MM.YYYY')
to_date(body->>'rank_acquisition_date', 'DD.MM.YYYY')

-- Full name as readable string:
initcap(lower(body->>'family_name')) || ' ' ||
initcap(lower(body->>'name')) || ' ' ||
initcap(lower(body->>'patronymic'))
```

## Processing Pipeline

### 1. Automatic linking to declarations_person

Match on full name + date of birth:

```sql
SELECT
    d.id        AS diplomat_id,
    d.body->>'family_name'  AS family_name,
    d.body->>'name'         AS name,
    d.body->>'patronymic'   AS patronymic,
    d.body->>'dob'          AS dob,
    p.id        AS person_id,
    p.birth_date
FROM jvirblis.diplomats d
JOIN public.declarations_person p
    ON lower(p.family_name) = lower(d.body->>'family_name')
    AND lower(p.name)       = lower(d.body->>'name')
    AND lower(p.patronymic) = lower(d.body->>'patronymic')
    AND p.birth_date = to_date(d.body->>'dob', 'DD.MM.YYYY')
WHERE d.person_id IS NULL;
```

Name-only match (to check for ambiguities before committing):
```sql
-- same query without the birth_date condition
-- 1 result = confident match; >1 = ambiguous, needs manual review
```

Apply confirmed matches:
```sql
UPDATE jvirblis.diplomats d
SET person_id = matched.person_id
FROM (/* match query above */) matched
WHERE d.id = matched.diplomat_id;
```

### 2. Volunteer table for manual linking

Records without an automatic match — maximum context for decision-making:

```sql
SELECT
    d.id                            AS diplomat_id,
    d.body->>'family_name'          AS family_name,
    d.body->>'name'                 AS given_name,
    d.body->>'patronymic'           AS patronymic,
    d.body->>'dob'                  AS dob,
    d.body->>'department'           AS department,
    d.body->>'position'             AS position,
    d.body->>'diplomatic_rank'      AS rank,
    d.body->>'rank_acquisition_date' AS rank_date,
    d.body->>'url'                  AS source_url,
    NULL::INTEGER                   AS matched_person_id,  -- filled by volunteer
    NULL::TEXT                      AS comment
FROM jvirblis.diplomats d
WHERE d.person_id IS NULL
ORDER BY d.body->>'family_name';
```

### 3. Creating new persons

For diplomats not yet in the database:

```sql
INSERT INTO public.declarations_person (family_name, name, patronymic, birth_date)
SELECT
    initcap(lower(d.body->>'family_name')),
    initcap(lower(d.body->>'name')),
    initcap(lower(d.body->>'patronymic')),
    to_date(d.body->>'dob', 'DD.MM.YYYY')
FROM jvirblis.diplomats d
WHERE d.id IN (...)  -- IDs confirmed as new after manual review
RETURNING id;
```

Then link the newly created persons back:
```sql
UPDATE jvirblis.diplomats
SET person_id = <new_person_id>
WHERE id = <diplomat_id>;
```

### 4. Copy birth_date to existing persons

```sql
UPDATE public.declarations_person p
SET birth_date = to_date(d.body->>'dob', 'DD.MM.YYYY')
FROM jvirblis.diplomats d
WHERE d.person_id = p.id
  AND p.birth_date IS NULL
  AND d.body->>'dob' IS NOT NULL;
```

### 5. Create events (diplomatic rank assignment)

Check first that events haven't already been created:
```sql
SELECT person_id, date, position
FROM public.events_event
WHERE type_id = 7
ORDER BY date DESC;
```

Then insert:
```sql
INSERT INTO public.events_event (
    person_id,
    type_id,
    date,
    position,
    url,
    is_shown,
    created_by_id,
    created_when
)
SELECT
    d.person_id,
    7,
    to_date(d.body->>'rank_acquisition_date', 'DD.MM.YYYY'),
    d.body->>'diplomatic_rank',
    d.body->>'url',
    true,
    73,
    now()
FROM jvirblis.diplomats d
WHERE d.person_id IS NOT NULL
  AND d.body->>'rank_acquisition_date' IS NOT NULL;
```

## General Conventions

### Naming and structure
- Always use `jvirblis.table_name` (schema-qualified)
- PK: `BIGINT GENERATED ALWAYS AS IDENTITY` (or `INTEGER` for compatibility)
- Audit fields: `created_at TIMESTAMPTZ DEFAULT now()`, `updated_at TIMESTAMPTZ DEFAULT now()`

### updated_at trigger (function already exists in DB)
```sql
CREATE TRIGGER trg_<tablename>_set_updated_at
BEFORE UPDATE ON jvirblis.<tablename>
FOR EACH ROW EXECUTE FUNCTION jvirblis.set_updated_at();
```

### Regex in PostgreSQL
```sql
-- Use ~ operator (not regexp)
WHERE name ~ ',\s*[0-9]{4}'
```

### Date from year (avoid type mismatch)
```sql
make_date(year::int, 1, 1)
```

### JSON import via Python

psycopg2.extras.execute_values(
    cur,

    [(psycopg2.extras.Json(row),) for row in batch],
